# บทเรียนและใบงาน STM32F410RB

ไฟล์นี้เป็นภาพรวมเดิม บทเรียนฉบับขยายพร้อม CubeMX, ตัวอย่างแกนหลัก, การทดสอบ และสรุปแยกทุก Lab อยู่ใน [LAB_SUMMARIES.md](LAB_SUMMARIES.md)

บทเรียนนี้เขียนสรุปใหม่จากหัวข้อในเอกสารที่ให้ ไม่ใช่การถอดหนังสือทั้งเล่ม ผู้เรียนใช้ STM32F410RB ให้เลือก MCU รุ่นนี้ในโปรเจกต์และใช้ pinout ของ package จริง รายละเอียดวงจรและโค้ด peripheral ขั้นสุดท้ายต้องปรับกับบอร์ดจริง

## บทเตรียม: C และการอ่านรีจิสเตอร์

**เป้าหมาย:** เข้าใจว่าคำสั่ง C เปลี่ยนบิตใดและกระทบฮาร์ดแวร์อย่างไร

Peripheral คือวงจรที่ CPU สั่งงานผ่าน memory-mapped registers ภาษา C จึงใช้ pointer หรือโครงสร้างจาก device header เพื่ออ่านเขียนตำแหน่งเหล่านี้ CMSIS ให้ชื่อรีจิสเตอร์ที่อ่านง่าย แต่การใช้ชื่อเหล่านั้นยังเป็น register programming ไม่จำเป็นต้องเขียนเลข address เองทุกครั้ง

ทบทวน `uint32_t`, binary/hex, `& | ^ ~ << >>`, pointer, struct, function และ `volatile` ซึ่งบอก compiler ว่าการเข้าถึงตัวแปรมีความสำคัญและค่าอาจเปลี่ยนจากภายนอก แต่ไม่ได้ทำให้การดำเนินการหลายขั้นเป็น atomic

```c
reg |=  (1UL << 5);  // set bit 5
reg &= ~(1UL << 5);  // clear bit 5
reg ^=  (1UL << 5);  // toggle bit 5
reg = (reg & ~(3UL << 10)) | (1UL << 10); // field [11:10] = 01
```

ตัวอย่างข้างต้นใช้กับตัวแปรจำลองหรือรีจิสเตอร์ read/write ที่อนุญาตเท่านั้น รีจิสเตอร์แบบ write-one-to-clear หรือ write-only ต้องใช้วิธีตามคู่มือ ห้ามใช้ read-modify-write โดยอัตโนมัติ

**ฝึก:** เริ่ม `reg=0x000000A0` แล้ว set bit 0, clear bit 7 และเปลี่ยน field [3:2] เป็น 10 ตามลำดับ เฉลย: `0xA1 → 0x21 → 0x29`

**งานส่ง:** วาด CPU → bus → RCC/GPIO และอธิบายว่าเหตุใดต้องเปิด peripheral clock ก่อนใช้งาน อ่านหนังสือบท 1, 5 และ RM0401 บท 5–6

## Lab01: LED และ SysTick

**เป้าหมาย:** ตั้ง GPIO output และสร้างช่วงเวลาจาก clock ที่ทราบค่า

GPIO output ต้องระบุ mode, output type, speed และ pull ขา PA5 ใช้ field MODER[11:10] เพราะแต่ละขาใช้ 2 บิต ส่วน ODR/IDR ใช้หนึ่งบิตต่อขา Output speed ควบคุมลักษณะขอบสัญญาณ ไม่ใช่ความถี่กระพริบ

SysTick เป็นตัวนับถอยหลัง 24 บิต ถ้า clock 16 MHz ต้องใช้ 16,000 clock ต่อ 1 ms ดังนั้น LOAD=15,999 การสลับ LED ทุก 500 ms ทำให้หนึ่งรอบติดและดับใช้ประมาณ 1 วินาที

**ขั้นตอน:** ตรวจวงจร LED → เปิด clock GPIO → ตั้ง output → ทดสอบติด/ดับ → เพิ่ม SysTick → เปลี่ยนช่วง 100/500/1000 ms

**ตรวจผล:** ดู MODER/ODR ใน debugger และวัดคาบด้วยเครื่องมือถ้ามี การมองด้วยตาบอกได้เพียงทำงานคร่าว ๆ ไม่ใช่หลักฐานความแม่นยำระดับ ms

**คำถาม:** ถ้า SysTick ใช้ 8 MHz ค่า LOAD ต่อ 1 ms เท่าไร? เฉลย 7,999

**อ่าน:** RM0401 §5.3.8 และ §6.4; หนังสือบท 6 และ §11.4 ตัวอย่างเต็มอยู่ใน LAB01_LED_SYSTICK.md

## Lab02: Button และ Debounce

**เป้าหมาย:** แยกระดับลอจิกออกจากเหตุการณ์กดปุ่ม

Input ที่ไม่มี pull อาจลอย ปุ่มต่อ GND พร้อม pull-up จะอ่าน 1 ตอนปล่อยและ 0 ตอนกด หน้าสัมผัสอาจเด้งหลายครั้ง จึงต้องยืนยันสถานะคงที่ก่อนนับเป็นเหตุการณ์

**อัลกอริทึม:** อ่าน raw → ถ้า raw เปลี่ยนให้จำเวลา → ถ้าคงเดิมเกินช่วง debounce ที่ทดลอง เช่น 20 ms ให้ยอมรับเป็น stable → สร้าง pressed event เฉพาะขอบปล่อยไปกด ค่า 20 ms เป็นจุดเริ่มทดลอง ไม่ใช่ค่าที่เหมาะกับปุ่มทุกตัว

**ขั้นตอน:** เลือกขา input → อ่าน IDR → แสดงสถานะผ่าน LED → เพิ่ม debounce ด้วยเวลา → แยก pressed/released

**ตรวจผล:** กดช้า 20 ครั้งและกดค้าง 3 วินาที ต้องนับ 20 ครั้งและไม่เพิ่มซ้ำขณะค้าง ทดลองกดเร็วเพื่อหาขีดจำกัดของการกรอง

**คำถาม:** ทำไม toggle LED ทุกครั้งที่อ่านค่า 0 จึงผิด? เพราะ main อ่านซ้ำหลายรอบระหว่างการกดครั้งเดียว ต้องตอบสนองต่อ event

**อ่าน:** RM0401 GPIO IDR/PUPDR; หนังสือบท 6

## Lab06: Timer และ Clock Tree

**เป้าหมาย:** สร้าง timebase ที่คำนวณได้ก่อนนำไปใช้ PWM

สำหรับ upcounter edge-aligned ที่ใช้ internal clock: `f_update = f_TIM / ((PSC+1)(ARR+1))` ต้องหา f_TIM จาก clock tree จริง เพราะไม่จำเป็นต้องเท่ากับ CPU clock และมีเงื่อนไข prescaler/TIMPRE ตามรุ่น

ตัวอย่างสมมติ f_TIM=16 MHz, PSC=15999, ARR=999 ได้ update 1 Hz ถ้า toggle LED ทุก update จะได้ LED ครบหนึ่งรอบทุก 2 วินาที

**ขั้นตอน:** เลือก timer ที่มีใน F410 → บันทึก clock source → คำนวณค่า → เปิด clock → ตั้ง PSC/ARR → โหลดค่าและจัดการ update flag ตามคู่มือ → start → ตรวจ update แบบ polling ก่อน

**ตรวจผล:** เปรียบเทียบ 100 ms และ 1 s กับการวัด อธิบายผลของการเปลี่ยน PSC เพียงตัวเดียว ระบุข้อจำกัด polling ที่อาจพลาดเหตุการณ์เมื่อ main ทำงานนาน

**คำถาม:** ต้องการ update 10 Hz ที่ f_TIM=16 MHz, PSC=15999 ใช้ ARR เท่าไร? เฉลย 99

**อ่าน:** RM0401 บท RCC และ TIM5; หนังสือบท 10–11

## Lab07: Interrupt และ Event

**เป้าหมาย:** ให้ CPU รับเหตุการณ์โดยไม่ต้องวนรออย่างต่อเนื่อง

EXTI จัดการขอบสัญญาณภายนอก ส่วน NVIC จัดการ interrupt ที่ส่งเข้า core ต้องตั้งทั้งแหล่งเหตุการณ์ เส้นทาง mapping mask/trigger และ NVIC ตามชนิด interrupt ISR ควรทำงานสั้น เช่น เก็บเวลา/เพิ่ม counter/ตั้ง flag แล้วให้ main จัดการงานแสดงผล

**ขั้นตอน:** เริ่ม timer interrupt → ตรวจชื่อ handler ใน startup → เปิด peripheral interrupt และ NVIC → เคลียร์ pending ตามคู่มือ → เพิ่ม EXTI button → debounce ใน main

**ตรวจผล:** ให้ LED ทำงานตามเวลาและกดปุ่มพร้อมกัน ต้องไม่มี delay ยาวใน ISR และไม่มี interrupt วนซ้ำจาก pending ที่ไม่ถูกเคลียร์ ถ้าใช้ flag เดียวให้ระบุว่าอาจรวมหลาย event เป็นหนึ่ง หากต้องนับครบให้ใช้ counter/queue และป้องกัน race ตอนอ่านหรือรีเซ็ต

**คำถาม:** volatile ทำให้ `count++` ปลอดภัยจากทุก race หรือไม่? ไม่ เพราะเป็นหลายขั้นตอน

**อ่าน:** RM0401 บท 9; หนังสือบท 7

## Lab03: UART

**เป้าหมาย:** ใช้ข้อความเป็นเครื่องมือสังเกตและสั่งงานระบบ

UART ต้องตกลง baud rate, data bits, parity และ stop bits ให้ตรงกัน ขา TX/RX ต้องเป็น alternate function ที่ถูกต้องและต่อไขว้ TX → RX พร้อม GND ร่วม ใช้ logic level ที่เข้ากันได้ ไม่ต่อ RS-232 voltage เข้าขา MCU โดยตรง

**ขั้นตอน:** ตรวจ USART และ AF ใน datasheet → เริ่ม 115200 8N1 โดยตรวจ baud error จาก clock → ส่งข้อความคงที่ → echo → รับคำสั่ง LED ON/OFF → เพิ่ม receive แบบ interrupt พร้อม buffer จำกัดขนาด

**ตรวจผล:** ส่งคำสั่งถูก ผิด ยาวเกิน buffer และไม่มี newline ต้องไม่เขียนเกินขอบเขตหรือค้าง ระบุว่า timeout ทำงานจาก timebase ใด

**คำถาม:** ส่ง 100 byte แบบ 8N1 ที่ 115200 ใช้เวลาโดยประมาณเท่าไร? `100×10/115200 ≈ 8.68 ms` ไม่รวมช่องว่างระหว่าง byte

**อ่าน:** RM0401 บท USART; หนังสือบท 8

## Lab04: PWM

**เป้าหมาย:** ปรับ duty โดยคงความถี่ และตรวจสัญญาณที่ขาจริง

สำหรับ PWM mode 1 แบบ active-high, edge-aligned upcount: `f_PWM=f_TIM/((PSC+1)(ARR+1))` และในช่วงทั่วไป `duty=CCR/(ARR+1)` ตัวอย่าง f_TIM=16 MHz, PSC=15, ARR=999 ได้ 1 kHz ค่า CCR=100/500/900 ให้ 10/50/90%

**ขั้นตอน:** เลือก timer/channel/AF pin ที่รองรับ → ตั้ง PWM → เริ่มที่ 0% → ทดสอบ 10/50/90% ด้วย LED → เปลี่ยน duty โดยใช้ preload ตามคู่มือ ถ้าใช้ TIM1 ต้องตรวจ main output enable ด้วย

**ตรวจผล:** วัด frequency และ high time ทุกค่า ความสว่างที่ตาเห็นไม่เป็นสัดส่วนเชิงเส้นกับ duty เสมอไป กรณี 100% ต้องตรวจขอบเขต CCR/ARR และความกว้าง register ไม่เพิ่ม ARR+1 จนล้น

**คำถาม:** จากตัวอย่างต้องการ 25% ให้ CCR เท่าไร? เฉลย 250

**อ่าน:** RM0401 TIM1/TIM5; หนังสือ §11.3.7

## Lab05: ADC

**เป้าหมาย:** เปลี่ยนค่าดิจิทัลเป็นค่าประมาณแรงดันพร้อมอธิบายความคลาดเคลื่อน

ADC 12 บิตให้ raw 0–4095 การประมาณแรงดันทั่วไปคือ `V≈raw×VREF/4095` ต้องใช้ VREF ที่ทราบหรือวัดได้ Sampling time และความต้านทานของแหล่งสัญญาณมีผลต่อการอ่าน

**ขั้นตอน:** เลือกขา ADC/channel ที่มีจริง → ตั้ง analog mode → ตรวจ ADC clock และ sampling time → อ่าน single conversion → ส่ง raw ทาง UART → แปลงแรงดัน → ลองเฉลี่ย 16 ตัวอย่าง

**ตรวจผล:** ทดลองแรงดันใกล้ GND กลางช่วง และใกล้ VREF ภายในช่วงอินพุตที่อนุญาต เทียบมัลติมิเตอร์ บันทึก min/max ก่อนและหลังเฉลี่ย การเฉลี่ยลด noise บางชนิดแต่ไม่แก้ VREF ผิด

**คำถาม:** raw=2048 และ VREF=3.3 V ได้เท่าไร? ประมาณ 1.6504 V

**อ่าน:** RM0401 บท 11; หนังสือบท 12; Datasheet electrical/ADC characteristics

## Lab08: I2C และ OLED

**เป้าหมาย:** เข้าใจ ACK และแยกปัญหา bus ออกจากคำสั่งควบคุมจอ

I2C ใช้ SCL/SDA แบบ open-drain พร้อม pull-up ตามแรงดันและโหลดที่เหมาะสม MCU ส่ง address แล้วตรวจ ACK ส่วนการวาดตัวอักษรต้องใช้ protocol ของ controller จออีกชั้นหนึ่ง ไฟล์ที่ให้มายังไม่ระบุ OLED controller หรือขนาดจอ จึงยังไม่กำหนด driver เฉพาะรุ่น

**ขั้นตอน:** ยืนยันรุ่นจอและแรงดัน → ตรวจ pull-up บนโมดูล → เลือก I2C instance/AF → ทดลอง transaction พร้อม timeout → ยืนยัน address แบบ 7 บิต → init ตาม datasheet จอ → แสดงข้อความ → แสดงค่า ADC

**ตรวจผล:** address ผิดต้องจบด้วย error/timeout ไม่ค้าง ถอดจอแล้วงานอื่นต้องเดินต่อ อธิบายว่าฟังก์ชันที่ใช้รับ address แบบ 7 บิตหรือแบบเลื่อนซ้าย ห้ามนำค่าของสองรูปแบบปนกัน

**คำถาม:** เห็น ACK แล้วจอว่างหมายความว่าอย่างไร? bus อาจสื่อสารได้ แต่ยังต้องตรวจ init, controller, framebuffer และคำสั่งส่งข้อมูล

**อ่าน:** RM0401 บท I2C ของ instance ที่ใช้ ซึ่งต้องแยกจาก FMPI2C; หนังสือบท 14; เพิ่ม datasheet จอเมื่อทราบรุ่น

## Lab09: Encoder

**เป้าหมาย:** แปลงลำดับสัญญาณ A/B เป็นทิศทางและระยะการหมุน

Quadrature encoder ให้ A และ B เหลื่อมเฟสกัน Timer ที่รองรับ encoder mode ใช้สองช่องรับเพื่อเพิ่ม/ลด counter ได้ ต้องตรวจขา AF คู่และโหมดการนับ x1/x2/x4 ก่อนใช้ค่า pulses per revolution

**ขั้นตอน:** ระบุว่าเป็น knob หรือ encoder เพลา → ตรวจสัญญาณและ pull → เลือก TIM1 หรือ TIM5 ตามทรัพยากรที่เหลือ → ตั้ง input/filter/encoder mode → อ่าน CNT → หมุนจริงหนึ่งรอบแล้วเทียบจำนวน count

**ตรวจผล:** หมุนทั้งสองทิศทางและผ่านจุด counter wrap ได้ สำหรับความเร็วใช้ `RPM=60×delta_count/(counts_per_rev×delta_t_seconds)` โดย delta_count ต้องแก้ wrap และ counts_per_rev ต้องรวม decoding multiplier และอัตราทดที่เกี่ยวข้อง

**คำถาม:** 400 count ต่อรอบ วัด 100 count ใน 0.5 s ได้เท่าไร? 30 RPM

**อ่าน:** RM0401 encoder interface ในบท timer; หนังสือ §11.3.9

## Lab10: PWM Motor

**เป้าหมาย:** ใช้ PWM สั่ง driver และอธิบายความต่างระหว่าง duty กับความเร็วจริง

GPIO ไม่ใช่แหล่งจ่ายมอเตอร์ ต้องใช้ driver ที่เหมาะกับชนิดมอเตอร์ แรงดันและกระแส โดยตรวจการป้องกันแรงดันย้อนจากวงจร/โมดูลที่ใช้ กำหนดไฟเลี้ยงและ GND ตาม datasheet driver เริ่มการทดลองจาก motor DC แบบ brushed หนึ่งตัวเมื่อยืนยันรุ่นแล้ว

**ขั้นตอน:** ทดสอบ PWM ด้วย LED ก่อน → ตรวจ truth table ของ driver → ตั้ง default disabled → ต่อระบบโดยยังไม่จ่ายไฟมอเตอร์ → เริ่ม duty ต่ำ → เพิ่มแบบ ramp → เพิ่มคำสั่ง stop → เพิ่มข้อมูล encoder ถ้ามี

**ตรวจผล:** เปิดเครื่องต้องหยุด, คำสั่งหยุดต้องตอบสนองตามเวลาที่กำหนด, เปลี่ยน duty แล้ววัดความเร็วจริง, reset แล้วไม่เริ่มหมุนเอง อย่าทดสอบ stall โดยไม่ทราบขีดจำกัดกระแสและอุณหภูมิ

**คำถาม:** duty 50% แปลว่า RPM ครึ่งหนึ่งของสูงสุดเสมอหรือไม่? ไม่ ขึ้นกับโหลด แรงดัน ความฝืด และคุณสมบัติมอเตอร์

**อ่าน:** บท PWM/Timer, เพิ่ม datasheet driver และ motor เมื่อทราบรุ่น
