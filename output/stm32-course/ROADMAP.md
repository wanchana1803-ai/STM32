# หลักสูตร STM32F410RB: จากพื้นฐานสู่ Register Programming

จัดทำจากไฟล์ที่ผู้เรียนให้ไว้ วันที่ 26 กันยายน 2026

## เป้าหมายและสมมติฐาน

เมื่อเรียนจบ ผู้เรียนจะอ่าน Datasheet และ Reference Manual เพื่อเลือกขา ตั้งค่า peripheral เขียนโปรแกรม ทดสอบ และอธิบายผลได้ด้วยตนเอง โดยทำครบ 10 Lab จากภาพ `10topic.png`

ผู้เรียนยืนยันว่าใช้ STM32F410RB แผนเริ่มต้นนี้ใช้เวลา 12 สัปดาห์ สัปดาห์ละ 6 ชั่วโมง รวม 72 ชั่วโมง โดยเวลาเรียนและพื้นฐาน C ยังเป็นสมมติฐานที่ปรับได้ ชื่อชิปยังไม่ได้ยืนยันว่าบอร์ดจริงเป็น Nucleo หรือมี LED ที่ PA5 ต้องตรวจชื่อบอร์ดและ schematic ก่อนต่อวงจร

แม้ไฟล์ datasheet ชื่อ stm32f410cb.pdf แต่เนื้อหาครอบคลุม STM32F410x8/B รวมรุ่น RB ด้วย ให้ใช้ตารางรุ่น STM32F410RB และผังขา package 64 ขาที่ตรงกับ suffix ของชิปจริง ไม่ใช้ผัง 48 ขาของรุ่น CB; รุ่น RB มี Flash 128 KB และ SRAM 32 KB ตามตารางหน้า 12 ส่วน RM0401 ใช้อ้างอิงการทำงานของ F410 ได้ร่วมกัน

ใช้ HAL เพื่อเรียนรู้ภาพรวมและเปรียบเทียบผล แล้วฝึก CMSIS/Register เพื่ออธิบายการทำงาน โดยบท GPIO และ SysTick มีตัวอย่างรีจิสเตอร์โดยตรง ส่วน peripheral ที่ซับซ้อนเริ่มจาก HAL และไล่ดูรีจิสเตอร์ตามคู่มือ

ผู้เรียนยืนยันว่าใช้ **STM32CubeMX สร้างโปรเจกต์** ทุก Lab จึงเริ่มจากเลือก MCU/ตรวจ `.ioc` → ตั้ง Pinout & Configuration → ตรวจ Clock Configuration → เลือก Toolchain/IDE ใน Project Manager → Generate Code → เพิ่มโค้ดใน USER CODE หรือไฟล์แยก → build/flash/debug ด้วย IDE ที่ใช้จริง ขณะนี้ยังไม่ได้ยืนยัน IDE; STM32CubeIDE ด้านล่างเป็นตัวเลือกตั้งต้นเท่านั้น

ใช้ `.ioc` เก็บการตั้งค่าและตรวจโค้ดหลัง regenerate เสมอ บทเริ่มต้นใช้ HAL timebase ที่ CubeMX สร้างไว้ ส่วนตัวอย่าง SysTick polling เป็นการทดลองแยก ไม่ควรนำไปแทน main ทั้งไฟล์ในโปรเจกต์ HAL โดยตรง

## รูปแบบเรียนในแต่ละสัปดาห์

1. อ่านและสรุปแนวคิด 60 นาที: วาดเส้นทางข้อมูลตั้งแต่ขาถึงรีจิสเตอร์
2. คำนวณและวางแผน 60 นาที: pin map, clock และ pseudocode
3. ลงมือ 150 นาที: ทำขั้นต่ำให้ผ่านก่อนเพิ่มความสามารถ
4. ทดสอบและ debug 60 นาที: เก็บค่าที่คาดหวังและค่าจริง
5. สรุป 30 นาที: อธิบายสาเหตุของข้อผิดพลาดและสิ่งที่แก้

## จุดตรวจความพร้อมก่อนเริ่ม

- บันทึกชื่อชิปเต็ม รุ่นบอร์ด แรงดันเลี้ยง debugger และเครื่องมือที่มี
- ระบุขา LED, Button, SWD และขาที่บอร์ดใช้ไปแล้วจาก schematic
- จัดทำตาราง pin allocation ป้องกัน UART, ADC, PWM, I2C และ encoder แย่งขา
- เตรียม LED พร้อมตัวต้านทาน, ปุ่ม, potentiometer และโมดูลตาม Lab ที่จะเรียน อุปกรณ์เฉพาะรุ่นให้เลือกหลังตรวจบอร์ด
- ใช้ STM32CubeIDE สำหรับเขียน/build/debug และ STM32CubeMX สำหรับตั้งค่า/สร้างโปรเจกต์ โดยตรวจขั้นตอนตามรุ่นที่ติดตั้ง ปัจจุบัน ST ระบุว่า CubeMX ไม่ได้รวมอยู่ใน CubeIDE แล้ว: [เอกสาร ST](https://wiki.st.com/stm32mcu/wiki/STM32CubeIDE%3ASTM32CubeIDE_introduction)
- Build โปรแกรมเปล่า เชื่อม debugger หยุดที่ main และดูตัวแปรให้ได้ก่อนต่ออุปกรณ์เพิ่ม

## จุดที่ปรับจากภาพประกอบ

1. `TICKINT=0` คือ SysTick polling ไม่มี SysTick interrupt ให้เรียกว่า “นับครบ 1 ms แล้วตรวจ COUNTFLAG”
2. `LOAD=16000-1` ใช้ได้เมื่อ clock ที่ป้อน SysTick เป็น 16 MHz และเลือก processor clock เท่านั้น สูตรทั่วไปคือ `LOAD = f_SysTick / 1000 - 1`
3. หาก HAL ใช้ SysTick เป็น timebase การเปลี่ยนไป polling และปิด interrupt อาจทำให้ HAL_Delay หรือ timeout ไม่เดิน ต้องเลือกผู้ดูแล timebase ให้ชัดเจน
4. ค่า PLL 84 MHz ในภาพเป็นตัวอย่าง ต้องตรวจ clock tree, voltage scale, Flash latency และข้อจำกัดของ STM32F410 จริงก่อนใช้ บทเริ่มต้นยังไม่เปลี่ยน PLL
5. PA5 เป็นตัวอย่างขา ไม่ได้ยืนยันว่าเชื่อม LED บนบอร์ดที่ผู้เรียนมี
6. Delay แบบวนลูปไม่รับประกัน 500 ms เพราะขึ้นกับ clock, compiler และ optimization
7. `ODR ^= mask` เป็น read-modify-write ส่วน BSRR ใช้ set/reset บิตเฉพาะโดยไม่ต้องอ่าน ODR เหมาะเมื่อมีผู้เขียนพอร์ตหลายส่วน ทั้งนี้ยังต้องกำหนดเจ้าของแต่ละขาให้ชัดเจน

## การประเมินผล

แต่ละ Lab ให้คะแนน 10 คะแนน: อธิบายแนวคิด 2, pin/clock/register plan 2, ทำงานตามโจทย์ 3, หลักฐานทดสอบ 2, วิเคราะห์ข้อผิดพลาด 1 ผ่านเมื่อได้อย่างน้อย 8 และเงื่อนไขผ่านของ Lab ครบ

บันทึกทุกครั้ง: รุ่นบอร์ด → เวอร์ชันเครื่องมือ → ผังต่อสาย → clock → ค่า register สำคัญ → expected/actual → ปัญหา → วิธีแก้ → สิ่งที่ยังไม่ยืนยัน

## โปรเจกต์ปลายทาง

สร้างตัวควบคุมมอเตอร์ DC แบบปรับ duty ได้ด้วย potentiometer หรือคำสั่ง UART แสดงค่า duty/ค่าที่วัดบน OLED และใช้ encoder วัดการหมุนถ้าติดตั้งกับเพลาจริง ถ้าเป็น rotary knob ให้ใช้เป็นตัวปรับคำสั่งแทน ห้ามเรียกค่า knob ว่า RPM ของมอเตอร์

เกณฑ์รับงาน: เริ่มเปิดเครื่องโดยมอเตอร์หยุด, เปลี่ยน duty แบบ ramp, ปุ่มหยุดมีลำดับความสำคัญสูง, UART รับคำสั่งผิดได้โดยไม่ค้าง, จอเสียหรือไม่ตอบไม่ทำให้ลูปควบคุมค้าง และมีหลักฐานทดสอบครบทุกสถานการณ์ การควบคุมความเร็วแบบป้อนกลับ PI/PID เป็นบทต่อยอดหลังงานพื้นฐานผ่าน
